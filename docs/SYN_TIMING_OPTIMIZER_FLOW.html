§3End-to-End Flow — 4 Steps

STEP 1READ
  • 1a — Inventory tune/FxSynthesize/, read every existing .tcl fully, find all tunesource lines
  • 1b — Locate QoR passes (FxSynthesize.pass_*.proc_qor.rpt.gz) — highest N is the primary dataset
  • 1c — Extract per-group timing for every pass: WNS, TNS, NVP, LOL, CritLen, Period
  • 1d — Read top-20 worst endpoints — reveals which modules are actually failing
  • 1e — Read worst-path traces for the top-3 groups — wire vs gate delay split, MB4/MB8 launch cells
  • 1f — Build the effective-weight map (last-sourced tune file wins on name conflicts)
  • 1g — Read override.params for compile-pass count and DEF path
  • 1h — Read FxSynthesize.dat for the authoritative DesignWNS/DesignTNS/DesignNVP — never derive the design total by summing the per-group table in 1c (double-counts shared endpoints)
Output: full tables — all groups × all passes × top-20 endpoints × weight map. No truncation.
↓
STEP 2DIAGNOSE — 7 Root-Cause Checks
  • Runs Checks A through G (detailed in §4 below) against the Step 1 data
  • Each check independently emits a verdict — FOUND/CLEAN, a cost table, or a fix list
  • Checks are prioritized: A > F > G > B,C > E > D — masking/missing-group bugs before weight tuning, weight tuning before physical bounds, physical bounds before RTL escalation
Output: one full table per check — nothing is ever silently skipped, even when a check is CLEAN.
↓
STEP 3SUGGEST — Propose All Changes
  • Builds a hierarchy map: group → endpoint prefix → get_cells filter, from real endpoint/path-trace data
  • Decides create vs. update for pre_opt.tcl, group_paths.tcl, r2r_optimization.tcl
  • Writes the complete TCL for every fix — group_path lines, create_bound blocks, compile-effort set_app_options — never abbreviated
  • No files are written yet in either mode — this step only proposes and reports
  • Always saves <tile_dir>/.optimizer_plan.json — a structured, machine-readable record of every fix
Output: fix list, full file diffs, expected WNS gain per fix, RTL action items table.
↓
STEP 4GENERATE — Write Tune Files
  • Full run: executes immediately after Step 3, using the plan just built
  • --apply run: loads the previously saved .optimizer_plan.json — stops if it's missing
  • Re-derives ESTIMATED bound coordinates against the real DEF if one has since become available
  • Write order: pre_opt.tcl tunesource → group_paths.tcl → r2r_optimization.tcl → override.params
Output: per-file line counts + CREATED/UPDATED status — "all changes match Step 3 proposal exactly."

§4The 7 Diagnostic Checks

A · Phantom Clocks > F · Missing Groups > G · I2R Split > B/C · Weights > E · Wire-Dominated > D · Arch Limits
A — Phantom Clock Paths structural
Detect: group with no scenario suffix, NVP > 500, |TNS| > 50,000 ps
Why: paths between mutually-exclusive modes dominate WNS/TNS and hide the real violations
Fix: split into one group per mode
F — Missing Groups structural
Detect: a module shows up in the top-20 endpoints but has no dedicated group_path -to
Why: its paths are being absorbed into a generic catch-all — invisible to targeted tuning
Fix: add a named group_path for that hierarchy
G — I2R Catch-All Split structural
Detect: SYN_I2R spans 2+ modules or 2+ clocks, or WNS improves <5 ps/pass
Why: one broad group dilutes optimization effort across unrelated hierarchies
Fix: split into per-module SYN_I2R_<module> sub-groups
B — Weight Starvation weight tuning
Formula: Cost = weight × NVP × |WNS|
Detect: Cost < 5% of the max cost across all groups
Fix: new_weight = clamp(round(sqrt(max_cost / (NVP×|WNS|))), 6, 16)
C — Override Conflicts weight tuning
Detect: same group_path -name X defined in both tune files with different weights
Why: the last-sourced file (r2r_optimization.tcl) wins silently — a group_paths.tcl weight can be quietly ignored
Fix: correct the weight in r2r_optimization.tcl to match intent
E — Wire-Dominated Paths physical
Triggers: CritLen > 95% of period & WNS < -30ps, or LOL < 15 & WNS < -50ps
Classify: hierarchical startpoint → BOUND (create_bound); bare I/O port → PORT-LIMITED (RTL action item only)
Fix: one dedicated create_bound per BOUND group, DEF-derived coordinates when possible
D — Architecture Limits escalation
Detect: LOL > 28 and WNS < -20 ps
Why: ~9.5 ps/gate × 30 levels ≈ 96% of a typical period — synthesis has no more logic-depth headroom
Fix: comment block only — escalate to the RTL team, synthesis cannot fix this

§6Key Principles

1Name groups before tuning weights. Named groups alone give the first WNS gain — a correctly-scoped group lets the optimizer focus effort where it actually matters.
2Effective weight = last-sourced file wins. r2r_optimization.tcl overrides group_paths.tcl silently on name collisions — always compute the effective weight, never assume the declared one.
3Cost = W × NVP × |WNS| reveals starvation. A group sitting at 2% of the max cost is functionally invisible to the optimizer no matter how bad its own WNS looks in isolation.
4Bounds: loose is safer than tight. Dense hierarchies target 40–65% utilization; congestion-sensitive ones target 10–20%. Tight bounds cause non-convergent placement.
5Arch limits need RTL, not synthesis. LOL > 28 with WNS < -20 ps means logic depth itself is the bottleneck — no tune-file change closes that gap.
6Safety-check after rebalancing. Recompute the full cost table after every weight change — no group should silently fall back below the 5% starvation threshold.

Six defined groups — SYN_R2R, umc_dat_r2r, umc_sec_r2r, umc_BEQ_r2r, SYN_R2R_2gclk, SYN_DFICLK — show zero paths. Config says 9+, the tool reports 7. Step 2 — What Check F found (the critical bug)

✗ Before — masked
group_path -name SYN_nonIP
  -from "full_name!~umc0/*"
  -to "full_name!~umc0/*"

Defined last in the file. No umc0 hierarchy exists in this design (real top-level modules: BEQ, umcctrl, umcsec, PHYINTF, ECC, WDB…) — so the filter matches every register. Last-definition-wins semantics means it steals every reg2reg path from the 6 specific groups defined above it.

✓ After — corrected
group_path -name SYN_nonIP
  -weight 6   (defined FIRST)

Moved to be the most general, first-defined group. The 6 specific groups (plus 3 new ones added by Fix F-2/3/4) are now defined after it and correctly claim their own paths. SYN_nonIP becomes what it was always meant to be — a residual bucket for genuinely unclaimed paths.

Proof, not just theory: SYN_nonIP's own worst path (BEQ/umcbeq_rd_comb/Fifo0Rdptr_reg[1] → ECC/ECCRD/DscEccSynd_d1_reg[28]) starts inside BEQ — which should have matched umc_BEQ_r2r's filter. It didn't. Direct confirmation the catch-all was grabbing paths it wasn't meant to.

Step 3 — The fixes proposed, and why (mapped back to the skill's own logic)

FF-1Check F
Reorder SYN_nonIP to be defined first, narrow its filter, bump weight 1→6.
Why: the skill's Check F rule is "general groups first, specific groups last" — Fusion Compiler resolves overlapping group_path matches by last-definition-wins. Putting the catch-all first means every later, more specific definition takes priority for its own matches.
FG-1Check G
Split SYN_I2R into 5 sub-groups: SYN_I2R_PHYINTF (w=8), SYN_I2R_BEQ (w=8), SYN_I2R_WDB (w=6), SYN_I2R_CLKGATE (w=6), residual SYN_I2R (w=6).
Why: Check G's split trigger fired on both conditions at once — endpoints span 5+ modules and WNS improvement fell from 3.12 ps/pass to 0.11 ps/pass by P3. A flat catch-all can't give any one module the weight it individually needs.
FB-1/2/3Check B
Weight bumps: clock_gating_default 1→8, io_to_flop 1→16, flop_to_io 1→16.
Why: Check B's cost formula (W × NVP × |WNS|) put every one of these under 2% of the max cost (SYN_nonIP at 133,852.9) — literally invisible to the optimizer's effort allocation regardless of how bad their individual WNS looked.
FE-1Check E
create_bound SYN_R2O_PHYINTF_bound — DEF-derived bbox (346.93, 148.93)–(473.76, 323.26) µm, 664 cells, density 0.03 cells/µm².
Why: SYN_R2O hit trigger T2 (LOL=2 < 15, WNS=-144.29 < -50 ps). Its dominant repeating pattern (PHYINTF/PHYIF_CHN*) has a hierarchical startpoint → BOUND-eligible. Two singular outlier paths (clock-gen sync, global alert) were deliberately excluded from this bound — they don't share the pattern and risk masking a real bug if force-fit into a placement fix.
Left as RTL action items, not auto-fixed: 3 paths whose startpoint is a bare I/O port (preUCLK, DAT_FEI_RdDatErr, DFICLK_ungated) were classified PORT-LIMITED by Check E — a placement bound cannot move a port. These need manual timing-intent review (set_false_path / set_multicycle_path) which is outside this skill's scope — it only ever touches synthesis tune files, never SDC/constraints.
